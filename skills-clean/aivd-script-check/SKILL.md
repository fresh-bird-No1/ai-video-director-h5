# 原文核对与修正

## 职责
把当前这一集剧本与 `sourceText` 逐场、逐行对照，找出说话人、台词、动作、场序、情节和资产上的偏差，只修被检测项命中的地方。最终结果必须能直接回写：先给检查结论和修改清单，末尾再给一个完整的 `kind` 为 `script` 的修正版 JSON。

## 读什么
- `sourceText`：本集已经拆好的原文，是判断对错的唯一依据。
- `data.script` 或 `scenes`：待核对的当前剧本，含每场的 `title`、`location`、`time`、`actions`、`narration`、`lines`、`durationSec`。
- 角色设计：`characters`、`characterNames`、`speakerAlias`，用来核对主称谓和别名映射。
- 角色卡的 `language`：用来判断台词语种是否匹配；但检查以 `sourceText` 为准，原文语种不能被翻译或改写。
- `data.assets.scenes` 与 `data.assets.props`：已有场景卡、道具卡名称，用来判断缺卡还是重名。
- 选题里的 `episodeDurationSec` 或 `topic.duration`，用来核对整集时长预算。
- 消息里若带 `places`、`props` 或上一轮修正结果，作为当前资产与文本基线一并核对。

## 怎么写

### 先认行，再检测
1. 当前剧本里，`actions` 每条是动作或画面，`narration` 每条是画外叙述，`lines` 每条是一个说话人的一句台词。先按这个结构认行，再逐项检测。
2. 只报真正不符合原文或不符合结构的行。已经正确的场次不要为了文笔重写，也不要补原文没有的戏。
3. 消息里即使出现 `action` 之类的旧字段，也不要切换成另一套输出格式；本技能始终只输出「文字结论 + 一个 `script` JSON」。

### 检测项与检查方法
1. **说话人错误。** 把每条对白的 `speaker` 与原文该句冒号前的人逐一对上；原文只有一个人在说，就不能写成「众人」「大家」；没有 `speaker` 的对白按原文补人，原文没人说就改成动作。仪器、扫描、读数、速率、百分比、时间戳、纯数字、屏幕、白板、字幕、记录、日志、系统、标注、广播、警报、对讲机本身不是说话人，遇到就改成动作；对讲机里若是某个角色在说，说话人写那个角色。
2. **台词被改写。** 把 `text` 与原文对应句子做逐字比对。允许的改动只有整句删除；换词、调序、合并、只留前半句、用省略号吞掉后半句都算改写。发现改写就回填原文原句，不加解释。
   - **语种不一致**也算改写：原文是外语、剧本被翻成中文（或反之），一律回填原文语种；角色卡 `language` 与原文不一致时只在文字结论里提示，不改台词。
3. **动作与对白混淆。** 动作行出现「角色名：台词」，或对白内容其实是可拍的动作、神态、括号提示、环境声，或一句叙述被切成「前半句当说话人、后半句当台词」，都要拆开：看得见的进 `actions`，真正开口的进 `lines`。两个角色的台词挤在一条里也要拆成两条。
4. **场次顺序错。** 给每场标出它对应的原文段落区间，区间必须按原文从前到后、互不穿越；后发生的段落被写到前面要挪回原位；下一集的内容被提前写进来要删除。
5. **原文情节遗漏。** 把原文逐段列出动作、转折和关键台词，逐项在场次里找落点。关键台词整句缺失的按原文补回；关键动作缺失的补进 `actions`；只补原文写到的东西。
6. **新增原文没有的内容。** 场次里每个人物、每句台词、每个动作都要能指回原文。原文没有的对白、动机、私下对质、后续剧情一律删掉；删除后若场次断开，只保留原文能支撑的过渡动作，不新编戏。
7. **旁白混入对白。** `speaker` 写成「旁白」「画外音」「OS」「VO」的，或 `lines` 里出现叙述性画外句的，移入 `narration`，不保留说话人。已经正确放在 `narration` 里的内容不要动。
8. **称呼不统一。** 同一个人只能用一个主称谓。`speakerAlias` 里的别称要换回 `characterNames` 里的姓名；名字后面不许挂情绪、渠道或动作，例如「老陈（通讯）」「宋瑶（自言自语）」都不合格，情绪和动作另写进 `actions`。原文里的称呼可以留在台词正文，但不能变成新的说话人。
9. **地点缺失。** 每场 `location` 必须非空，并且使用原文里的地名；`title` 不能代替地点，剧情句子也不能当地名。地点或时间变了却没换场，要拆场；同一地点、同一时段被无必要拆成多场，可以并场，但不得改变原文顺序。
10. **时长缺失。** 每场 `durationSec` 必须是正整数。缺失或为 0 时，按对白每秒约 4 个字、动作按实际演出时间补估。整集合计要与 `episodeDurationSec` 一致；没有该字段时从 `topic.duration` 解析；两者都没有时按 90 秒估算，偏差不超过 5 秒。只有被改场次或缺失场次需要重估，原本已有正整数的未点名场次不动。
11. **场景卡缺失。** 把每场 `location` 与 `data.assets.scenes`、本集已有的 `places` 对照。原文实际出现、两边都没有的地点，补进输出顶层的 `places`，字段写 `name`、`description`、`location`、`lighting`、`landmark`、`style`。已有卡不重复、不改名。
12. **道具卡缺失。** 把原文反复出现、需要单独出图的关键物件，与 `data.assets.props`、本集已有的 `props` 对照。缺的补进顶层 `props`，字段写 `name`、`description`、`usage`、`material`、`size`、`style`。衣服、发型、妆面和脸不算道具；已有卡不重复。
13. **镜头与场记混入正文。** 正文里出现镜号、特写、近景、远景、淡入淡出、切、「切黑」、出图提示词，或「场景概要」「出场角色」「戏剧目标」「情绪基调」「本场悬念」「下场预示」这类场记，全部删除；看得见的动作保留。
14. **资产字段写进正文。** 正文里出现画风或品类说明、单独的光线描述、材质磨损、尺寸、地标枚举，移到 `places` / `props`，正文只留可见画面和台词。

### 修改原则
1. 只改命中检测项的行。没有被点名的场次、台词、动作和时长保持原样，连标点都不要顺手改。
2. 台词只能整句删除或回填原文，不能润色、不能口语化重写。
3. 无法判断对错时保留原样，并在文字清单里标「存疑」，不要擅自改。
4. 每条修改都要能指回原文的具体句子、动作或段落。

## 输出

### 第一步：文字结论
先写一段总览：检查了哪些场、共发现几处问题、是否涉及缺卡。没有问题时直接写「按检测项逐条核对，未发现需要修正的地方」。

再列修改清单，一行一处：
- 第 N 场第 M 行｜检测项｜修改前「……」→ 修改后「……」
- 第 N 场｜检测项｜修改前「……」→ 修改后「……」

最后单列需要补的场景卡或道具卡；没有就写「无需补卡」。

### 第二步：完整修正版 JSON
末尾附一个 `JSON` 代码块，`kind` 固定为 `script`。`data` 含 `episodeNumber`、`title`、`scenes`，以及需要补的 `places`、`props`。

- `scenes` 必须输出**全部场次**，不能只给改过的几场，否则回写会覆盖掉其他场次。
- 未改动的场次和行逐字保留，包括原有的 `durationSec`；改过的行只改必要字段。
- 没有要补的资产时，`places`、`props` 写 `[]`。
- 不要输出 `scriptCheck`、`issues`、`edits`、`consistent` 这类 H5 不认识的顶层结构。

下面示例假设整集预算为 60 秒，两场相加 34 + 26 = 60，且两个地点都已有场景卡，所以 `places` 为空；实际输出按核对结果补缺。该示例可直接 `JSON.parse`：

```json
{
  "kind": "script",
  "data": {
    "episodeNumber": 3,
    "title": "门后的名字",
    "scenes": [
      {
        "title": "夜归",
        "location": "老宅客厅",
        "time": "夜",
        "actions": [
          "林晚推门进屋，湿伞尖在地砖上拖出一道水痕。",
          "她停在茶几前三步远，看着第二只还冒热气的杯子。"
        ],
        "narration": [],
        "lines": [
          { "speaker": "林晚", "text": "屋里谁来过？" },
          { "speaker": "周叔", "text": "你父亲回来过。" }
        ],
        "durationSec": 34
      },
      {
        "title": "楼梯口",
        "location": "老宅楼梯",
        "time": "夜",
        "actions": [
          "周叔横过身挡在楼梯口。"
        ],
        "narration": [],
        "lines": [
          { "speaker": "周叔", "text": "上面不能去。" },
          { "speaker": "林晚", "text": "那你就让开。" }
        ],
        "durationSec": 26
      }
    ],
    "places": [],
    "props": []
  }
}
```

文字清单示例（写在 JSON 之前）：
- 第 1 场第 1 行｜说话人错误｜修改前「周叔：屋里谁来过？」→ 修改后「林晚：屋里谁来过？」

用户点击「写入草稿」之前，不得声称已经写入项目。

## 硬性约束
- 先文字、后 JSON；JSON 的 `kind` 只能是 `script`，不得发明新的检查结果类型。
- 必须输出完整 `scenes`，未点名场次与台词逐字保留，不得整场重写。
- 台词只允许整句删除或回填原文，禁止换字、改语气、合并句子，也禁止翻译成角色卡 `language`。
- 不新增原文没有的人物、台词、动作、动机和结局；不调整未被点名的场序。
- `places` / `props` 只补现有资产没有的条目，不重复、不改已有名称。
- 不改 `episodeNumber`；`title` 只有在明显错字且原文能佐证时才动。
- 无法判断的地方保留原样并标「存疑」，不能借检查之名自由创作。
- 末尾 JSON 必须能直接解析回写，代码块外不得再放第二份完整 JSON。

## 交付前自检
- 十四条检测项是否都过了一遍，而不是只查了说话人和台词。
- 每条修改是否都能指回原文的具体句子或动作，文字清单是否写了「修改前 → 修改后」。
- 未改动的场次、行和 `durationSec` 是否逐字保留。
- 台词是否做到只删整句或回填原句，没有改写。
- 台词是否保留原文语种；角色卡 `language` 与原文不一致时是否只提示、未擅自翻译。
- 所有 `location` 是否非空并使用原文地名，所有 `durationSec` 是否为正整数。
- 缺失的场景卡、道具卡是否补进顶层数组，已有资产是否没有重名。
- `kind` 是否为 `script`，`scenes` 是否为全集，JSON 能否被 `JSON.parse` 直接解析。
