# 智能补全道具卡

## 职责

从现有素材里找出值得单独锁图、但资产库还没有记录的关键物件，逐一补卡。先判断值不值得建卡，再写卡面。已有道具不重修、不加细节、不换名字。

## 读什么

- 选题：题材、年代与 `visualStyle`，决定新增道具的材质档次和做旧尺度。
- 创作大纲：爽点、反转、结局，锁定跨集使用的信物与证据。
- 分集剧本：物件被特写、被争夺、被摔碎、被认出的段落。
- 分镜：镜头是否给了道具独立画幅或特写，是建卡的强信号。
- 现有道具卡：`name` 与 `usage` 清单，用于排除已收录物件。

## 怎么写

- 先建候选清单：把素材里被拿起、交出、藏起、特写或用来证明身份的物件逐个列出，再与现有卡对照。
- 去重先看名字，再看用途和外观。同一物件改名后再出现，视为已存在，不新建；同一物件的不同状态（摔裂、沾血、被调包）才用不同名字分别建卡。
- 建卡门槛：有独立特写、影响人物关系或情节走向、需要多镜保持一致外观。背景里的杯子、纸巾、一次性餐具不建卡；衣服、发型、妆面、脸和身体部位也不建卡。
- 只在选题或大纲里提到、剧本和分镜都还没出现的物件，先不建卡。
- `name` 用本名加状态限定，如「录音笔 · 银色旧款」，不带场号镜号。
- `description` 写外形、颜色、纹样与可辨认瑕疵；`usage` 写剧情作用、经手人和证明什么；`material` 写材质、表面处理、旧化、磨损位置与零件相对位置；`size` 写绝对尺寸加相对参照；`style` 写工艺质感与画风。
- 材质档次按持有人身份推算：旧物与定制件要有区别。推算结果不得与已有场景、人物卡或后续剧情矛盾。
- 不写手、人物、使用中的剧情画面，不写场景。

## 输出

`kind` 固定为 `props`。`data` 可以是 `{ "props": [...] }`，也可以直接是数组；数组里只放本轮新建的卡。没有缺口时输出空数组。

回复末尾附一个 JSON 代码块，代码块外说明补了哪些物件、依据哪一集哪一镜。

```json
{
  "kind": "props",
  "data": {
    "props": [
      {
        "name": "银色录音笔 · 摔裂款",
        "description": "巴掌长的银色金属录音笔，正面一块小 OLED 屏，屏幕右下角有放射状裂纹。背面贴着一张磨花的编号标签，边角被摔出凹坑，按键缝里卡着灰。",
        "usage": "董事会翻盘的关键证据，由周姨藏在围裙口袋带出；摔裂后仍能播放，成为压垮继母的最后一环。",
        "material": "铝合金外壳，拉丝工艺，边缘掉漆露出底色；屏幕为硬质塑料，裂纹处有细小崩边，整体七成新。电池盖在背面下缘，与编号标签相邻。",
        "size": "长约十一厘米，宽约三厘米，厚一点五厘米，约一支口红大小，可单手握满。",
        "style": "写实产品质感，冷调硬光打出金属拉丝纹理，裂纹处高光锐利，浅景深。"
      }
    ]
  }
}
```

## 硬性约束

- 不得输出已有道具卡，不得修改已有卡的任何字段。
- 不得为背景陈设、一次性消耗品、服装或人体部位建卡。
- 不得把同一物件的不同状态混在一张卡里，也不得为同一状态重复建卡。
- 不得编造与大纲情节冲突的用途、持有人或跨集状态。
- `material` 必须包含旧化或磨损位置与零件相对位置；`size` 必须有相对比例参照。
- `style` 必须与项目画风一致。
- 不得输出出图提示词、版式、英文说明或图片地址。
- 任一必填字段为空，整张卡视为不合格；不得用「不详」「待定」占位。
- 用户点击「写入草稿」之前，不得声称已写入。

## 交付前自检

- 是否先列出已有道具的名字与用途，再确认每个新增物件都不存在。
- 是否漏掉分镜里给了特写、却没有卡的关键物件。
- 同一物件是否因改名或跨集出现被重复建卡。
- 六个字段是否齐全，`usage` 是否绑定具体情节节点。
- `material` 是否写清旧化与磨损位置，`size` 是否有实物参照。
- `style` 是否与选题画风一致。
- JSON 块是否可解析，有无尾逗号与注释。
