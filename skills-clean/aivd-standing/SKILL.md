# 站位卡设计

## 职责

为一场戏里真正有调度价值的瞬间建一张站位卡。卡面回答：谁站在哪、朝哪边、彼此隔多远、被什么光打、以什么固定物件为参照。它让同一场戏在不同镜头之间不掉位置，不负责写台词，也不负责出图和写提示词。

## 读什么

- 选题：画风与调性，决定站位图是写实还是风格化。
- 创作大纲：人物关系与权力变化，是判断站位意图的依据。
- 分集剧本：场次编号、地点、时间、动作与走位描写。
- 分镜：镜号、景别、机位和画面描述，用来把站位绑定到具体画幅。
- 场景卡：门位、家具方位与固定地标，站位必须与之吻合。
- 现有站位卡：名字、集数、场次、镜号清单，避免重复。

## 怎么写

- `name` 用能识别场次的短名，点明调度关系，如「第3集 包厢对峙 · 隔桌站立」，同一集内不得重名，不能用「新站位」「未命名」。
- `episode` 写整数集数，不带「第」字、不带范围。
- `shot` 必须同时写明场次与镜号，格式如「第2场 · 镜3-4」或「第2场 · 镜5」，禁止只写「某镜」、只写集数或留空。没有分镜表时写剧本里可对应的动作节拍，并注明「暂无分镜号」，但场次仍要写全。
- `function` 用一句话写这个瞬间的叙事目的：谁压谁、谁占住门或主位、距离是拉近还是推远、谁被迫后退。写权力关系和空间变化，不堆情绪形容词。
- `description` 写可执行的调度细节：每人相对位置、身体朝向、视线落点、两人间距（用「一步」「半臂」这类可感知单位），以及谁挡门、谁贴墙、谁在物件与门之间。
- `lighting` 写光源方向与每个关键人物的受光面，如「窗光从左侧打入，女主右脸亮，男主逆光成半剪影」；夜景要说明主光来自哪盏灯。
- `landmark` 写站位参照物，优先引用场景卡已有的固定地标，说明谁靠着、谁挡着、谁在地标与门之间。
- `style` 写画风与镜头气质，与项目画风锁定一致。
- 可选字段 `sceneName` 填所在场景的资产名，`characterNames` 列入画角色名，`propNames` 列需要锁外观的道具名；名字要与资产库一致，没有对应项时用空数组或空串。
- 分镜没给走位时，按 `function` 反推最简调度，不额外加人、不加复杂动作，不得虚构剧本里不存在的调度。
- 单卡补全：用户从某张卡点「补全信息」时，只处理这一张，补空缺、润色已有内容，非空字段保持原意；不得改动其他站位卡。

## 输出

`kind` 固定为 `standings`。`data` 可以是 `{ "standings": [...] }`，也可以直接是数组。每张卡必须包含 `name`、`episode`、`shot`、`function`、`description`、`lighting`、`landmark`、`style` 八个非空字段。

回复末尾附一个 JSON 代码块，说明写在代码块外。

```json
{
  "kind": "standings",
  "data": {
    "standings": [
      {
        "name": "第3集 包厢对峙 · 隔桌站立",
        "episode": 3,
        "shot": "第2场 · 镜3-4",
        "function": "继母占住主位与门口，女主被逼在转盘另一侧，用一张桌子的宽度表现她暂时没有还手余地。",
        "description": "继母立于圆桌北侧主位，身体正对镜头，双手撑桌；女主在桌子南侧偏右，侧身朝向门口，视线越过转盘落在继母手上。两人隔桌约两步，周姨缩在门内左侧半步，背贴墙。",
        "lighting": "顶部射灯从正上方压下来，继母面部亮、眼窝落影；走廊冷光从女主背后渗入，她正面处于暗部，只余肩线一道亮边。",
        "landmark": "圆桌中央的青铜花插隔在两人之间；继母右手边是主位椅背；女主左后方半步是墙角衣帽架。",
        "style": "写实都市剧质感，冷调低饱和，中景平视，浅景深压暗背景。",
        "sceneName": "君悦酒店 · 二层包厢",
        "characterNames": ["继母", "女主", "周姨"],
        "propNames": []
      }
    ]
  }
}
```

## 硬性约束

- `episode` 必须是整数，`shot` 必须能定位到场次与镜号，两者缺一不可。
- 不得为没有调度意义的画面建卡，如单人特写、纯空镜、纯道具特写。
- 不得虚构剧本和分镜里不存在的走位、人物或动作。
- 不得与场景卡的地标、门位、家具方位冲突。
- 不得改写已有站位卡，不得同名新建；单卡模式只改用户当前点名的那一张。
- `function` 必须写出权力关系或距离变化，不能只复述画面。
- 不得用「若干人」「适当距离」「附近」这类模糊表述。
- 任一必填字段为空，整张卡视为不合格；`sceneName` 对不上时也必须给地点短名。
- 不得输出出图提示词、版式说明、英文段落或图片地址。
- 用户点击「写入草稿」之前，不得声称已经写入。

## 交付前自检

- 集数、场次、镜号是否三者齐全且互相吻合。
- `function` 是否写出了权力关系或距离变化。
- `description` 是否能让第二个人照着摆位，朝向与间距是否明确。
- `lighting` 是否分别交代了每个关键人物的受光面。
- `landmark` 是否与场景卡一致，是否写明谁靠着或挡着。
- `sceneName`、`characterNames`、`propNames` 是否与资产库原名一致。
- `style` 是否与项目画风一致。
- 是否误改或重复新建已有站位。
- JSON 块能否解析，有无尾逗号与注释。
