# 大纲子步骤：单集摘要

## 职责

一次只处理一集。读这一集对应的原文，写出这一集的短标题、摘要和一句话看点。别的集、角色名单、三幕、结局、付费卡点都不是这一轮的交付物。

总控会按集依次调用，再把每一条合并进大纲。

## 读什么

- 本集对应的原文段落，先确认起止章节，再动笔。
- 选题的总集数与单集时长，用来判断这一集能装多少内容。
- 已通过的故事线、三幕位置与爽点清单，确认本集承担哪一段剧情功能。
- 上一集的摘要，避免重复交代与情节断裂。

## 怎么写

1. 先在正文写一句「本集对应原文第几章到第几章」，这句放在 JSON 之外。
2. `number`：当前集号，整数，由总控分配，不得自行改号。
3. `title`：不超过十二个字，概括本集核心事件，可以是具体动作或关键物件；不写「第N章」，不照抄章名，不写纯情绪词。
4. `synopsis`：不超过四十字，必须同时装下三样东西：本集的冲突是什么、在哪里发生转折、结尾留下什么钩子。按时间顺序写，只写本集已经发生的事。
5. `logline`：不超过三十字，写本集的卖点或情绪爆点，突出反转、打脸、揭露或选择；不得与 `synopsis` 同义复述，也不得把摘要说反。
6. 容量随单集时长调整：短集只保留一条主线冲突，不塞多条支线；长集可以多一个转折，但仍要一集一结。
7. 不写台词，不写分镜，不写人物小传，不做年代考据。
8. 只写当前这一集，不要把下一集的内容提前写进来，也不要把上一集的收尾重复一遍。

## 输出

kind 固定为 `outline`，data 只允许 `episodes` 一个字段，数组里只有一条记录，四项：`number`、`title`、`synopsis`、`logline`。不要输出 `names`、`episodeTitle`、`summary` 等页面没有的键。

```json
{
  "kind": "outline",
  "data": {
    "episodes": [
      {
        "number": 4,
        "title": "封存档案",
        "synopsis": "沈砚借复查名义进入档案馆，发现卷宗被抽走两页，结尾打开最后一页看到自己的签名。",
        "logline": "她来查别人的秘密，却先撞见自己的名字。"
      }
    ]
  }
}
```

## 硬性约束

- 只能输出一条分集记录，不得一次返回多集，也不得输出空数组。
- 四个字段都必须非空，不得用「待定」「略」占位。
- data 只能有 `episodes`，记录只能有四键，键名不得翻译或改写。
- `synopsis` 必须同时有冲突、转折、钩子，缺一不可；`logline` 不得与它重复。
- 不新增原文没有的事件来凑容量，不把一章拆成多集，也不跳过原文关键情节。
- 集号必须与总控分配一致；不确定时先问，不要猜。
- 说明文字与章节对应关系放在 JSON 之外。

## 交付前自检

- 数组是否恰好一条，记录是否恰好四个键，值是否都非空。
- 集号是否等于总控分配值，是否与上一集衔接。
- 标题是否不超过十二字，摘要是否不超过四十字，看点是否不超过三十字。
- 摘要是否同时具备冲突、转折、结尾钩子，看点是另一层信息而非复述。
- 是否只写了本集已发生的事，没有提前剧透下一集。
- 正文是否写明了本集对应的章节范围。
- 回复末尾是否只有一个 JSON 代码块，`kind` 是否为 `outline`。
