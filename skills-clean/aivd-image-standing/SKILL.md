# 站位图提示词

## 职责
写一张站位主图：整幅画面只有一个机位、一个瞬间，用来锁住这一场里人物的相对位置、朝向、距离与空间关系；同时输出本站位要一起送进出图流程的参考图清单。画面要能让人一眼读出谁在左、谁在右、谁在前、谁在后、各自面向哪里。这是调度示意，不追求表演细节，也不是多格分镜。

## 读什么
- 站位卡的名称、场次、分镜、叙事功能、`lighting`、`landmarks`、`styleLock`、`styleNotes`、`aspect`。
- 出场角色名单与各自的角色卡：姓名、外形要点、已有定妆图。
- 场景卡：空间形状、地标、门窗与主要通道。
- 剧本里这一段的动作关系：谁面向谁、谁背对谁、视线落在哪里。
- `availableLibrary`：资产库里可作参考图的角色、场景、道具，以及是否已有设定图。

缺项时按调度逻辑补足站位，并在图外说明里点明是推断；不擅自加人或换场景。

## 怎么写

第一行写固定标题：`站位主图`。之后分段，段首用固定标记，段间换行。整图只有一张主图，正文用简体中文，不要写镜头运动。

### 【站位】
- 若有参考图，段首按 `referenceImages` 的顺序逐条声明：`参考图1是角色「果果」`、`参考图2是场景「邮局门口」主图`。名字必须与资产库原名完全一致。
- **参考图 N 严格对应第 N 项**：正文里每写到「参考图N」，所指的主体只能是 `referenceImages[N-1]`。参考图1是张三，就只能写「张三外貌跟参考图1」，不能挪给李四。
- 没有可用参考图时，`referenceImages` 与 `refs` 都是空数组，正文不得出现「参考图1」。
- 角色外貌锁对应角色参考图，场景布局锁场景参考图，关键道具外观锁道具参考图；没有参考图的项按资产卡描述写，不另起一套。
- 写清机位高度与取景范围：平视、略俯或四十五度俯视，画面覆盖整块调度区。
- 逐人写清五件事：在画面左 / 右 / 居中、在前景 / 中景 / 后景、脚踩地面、身体朝向（面向谁或哪面墙）、面部朝向与视线落点。
- 距离写成可复原的关系：相距约两步、隔着一张桌子、站在门内侧一臂之遥；谁挡住谁、挡住多少也要写。
- 多人时用「A 在 B 的左后方约两步」这类相对描述；不得让人物挡住关键地标，也不得互相遮住脸。
- 所有位置、朝向、前后关系必须能让人从文字复原出一张站位图。

### 【空间】
- 场景落在可复用的空间里，写清入口方向、两三个关键地标的画面位置。
- 有场景参考图时，空间、光线与主要物件跟那张图，不换成另一个地方。

### 【光线】
- 优先使用 `lighting`：主光来自哪一侧、人物与地面投下什么方向的影子、色温与场景一致。
- 不另起一套与场景矛盾的时间。

### 【道具】
- 写清关键道具在谁手里、在哪件家具上、离谁多远。
- 有道具参考图时锁外观；没有时按道具卡写，不加剧情里没有的物件。

### 【画风】
- 单独起行，放在【负面】之前。按 `styleNotes` 展开笔触、色调、光质、边缘与质感；为空时对齐 `styleLock`。
- 人物外形与服装保持角色卡设定，画面偏调度示意，干净清楚。

### 【负面】
- 最后单独一行，只列要排除的画面，用逗号分隔。

## 整图禁止
多格分镜、四向机位、纯文字说明条、UI 标注线、编号标签、台词气泡、箭头指示牌（故事里真有路牌除外）、名单外的角色、纯空景、遮挡关键地标、改变场景布局。

## 输出
先用一两句中文说明站位逻辑与参考图选择，再在回复末尾附一个 JSON 代码块：

```json
{
  "kind": "standingPrompt",
  "data": {
    "name": "邮局门口对峙",
    "prompt": "站位主图\n【站位】参考图1是角色「果果」。参考图2是角色「老钟」。参考图3是场景「邮局门口」主图。中景平视，略高于人物胸口。果果站在画面左侧靠近木牌，脚踩青石地面，身体面向右，脸转向柜台，视线落在老钟脸上，外貌跟参考图1；老钟站在画面右侧柜台后，身体面向左，视线落在果果眼睛，外貌跟参考图2；两人相距约两步，柜台在两人之间偏右。空间布局跟参考图3。\n【空间】门口青石地面，木牌在左，柜台在右，门洞在画面深处。\n【光线】夜景，主光来自右上灯笼，人物影子落向左下。\n【道具】果果右手提一盏纸灯，灯在身体右侧；柜台上的铜铃离老钟一臂。\n【画风】暖夜色，笔触与色调按 styleNotes 展开。\n【负面】多格分镜，四向机位，文字标注，编号标签，箭头，名单外角色",
    "negativePrompt": "multi-panel storyboard, four-direction views, text labels, numbered tags, arrows, extra characters, empty scene, blocking key landmarks",
    "refs": ["果果", "老钟", "邮局门口"],
    "referenceImages": [
      { "type": "character", "name": "果果" },
      { "type": "character", "name": "老钟" },
      { "type": "scene", "name": "邮局门口" }
    ]
  }
}
```

- `name` 与站位卡名称一致。
- `prompt` 第一行是固定标题，后面是分段纯文本，不含 Markdown 标题与解释。
- `refs` 是按出图顺序排列的资产名数组；`referenceImages` 是同一顺序的结构化清单，每项只含 `type` 与 `name`。
- `negativePrompt` 与正文【负面】一致，可省略但不能写图片地址。

## 硬性约束
- kind 固定 `standingPrompt`；data 至少含 `name` 与 `prompt`。
- **必须保留 `refs` 字段**，即使是空数组也不能删；可同时给 `referenceImages`。
- `referenceImages` 每项形如 `{"type":"character|scene|prop","name":"资产原名"}`；`refs` 与它顺序一致、名字一致。
- 只从 `availableLibrary` 里选参考图；优先选已有设定图的项，没有设定图的不硬写进清单。
- `prompt` 首行只能是 `站位主图`。
- 「参考图 N」与清单第 N 项严格对应，不得错位或编造编号。
- 单幅画面，不得输出第二张备选站位或多格分镜。
- 不输出图片地址，不调用出图，不声称已经写入资产卡。

## 交付前自检
- 首行是否为 `站位主图`，正文是否没有 Markdown 标题。
- `refs` 是否存在，`referenceImages` 的顺序、类型与名字是否和它一致。
- 正文的「参考图N」是否严格指向第 N 项，是否没有编造编号。
- 每个人的左右、前后、身体朝向、面部朝向、视线、距离是否都能读出来。
- 是否写明机位高度与取景范围，是否只有一张主图。
- 是否没有名单外角色、文字标注、箭头与多格分镜。
- JSON 是否能被 `JSON.parse` 解析，kind 与字段是否正确。
