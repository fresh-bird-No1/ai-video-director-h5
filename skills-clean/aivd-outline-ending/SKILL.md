# 大纲子步骤：爽点、结局与付费卡点

## 职责

只负责三块内容：找出原文里真正能兑现的爽点，写清结局落在哪一场戏，确定付费卡点卡在第几集、卡什么。角色名单、世界规则、故事线、三幕、分集摘要都不由你输出。

## 读什么

- 原文全文，重点标记身份揭露、当众反击、误会解开、权力反转、情感确认这些节点。
- 选题页的结局枚举、集数、调性与受众。
- 已通过的故事线与三幕，确保爽点落在冲突升级的位置，而不是平铺日常。

## 怎么写

### 爽点

`highlights` 是一段文字，先给配比，再逐条列兑现动作。

1. 配比按原文实际读感写，例如「打脸35% / 甜宠25% / 虐心20% / 逆袭15% / 燃5%」，合计一百，不要写成对象或数组。
2. 逐条写「第几集 + 谁做了什么 + 兑现了什么情绪」，四到八条。
3. 每条都要可拍可演，能落成具体动作、台词或场面；禁止只写「很爽」「全场震惊」「观众沸腾」。
4. 优先取原文已有的动作与反转，不凭空发明大场面，也不把同一动作换个说法重复计数。

### 结局

`ending` 是一段文字，开头必须先给类型，只能是 `HE`、`BE`、`OE` 三个字母之一：

- `HE`：原文收在赢了、团圆、心愿达成。
- `BE`：原文收在失败、死亡或关系破裂。
- `OE`：原文停在悬念、新威胁或留白，尚未分出胜负。

类型之后依次写：主线结局、人物关系落点、回收了哪些伏笔、全剧最难忘的一个情绪锚点、最后一场戏的地点与动作与情绪。原文没有感情线，就不要新编恋爱；原文没写完，不要补一个大团圆。类型以原文实际收尾为准，不为了贴合选题旧值改判。

### 付费卡点

`paywall` 是一段文字，每条卡点写四样：

1. 卡在第几集结尾，集号必须是已经存在的一集。
2. 卡点类型，例如身份危机、证据被夺、关系摊牌、限时选择。
3. 人物当时的处境与悬而未决的具体问题。
4. 下一集靠什么把观众拉回来。

卡点数量约为总集数的一成到一成五，至少一个；位置落在前半程末尾或中段转折，不能卡在情绪平缓的过场，也不能紧贴结局。悬念必须是本集已经埋下、下一集将解的，不得为卡点编造原文没有的事件。

## 输出

kind 固定为 `outline`，data 只允许三个字段：`highlights`、`ending`、`paywall`。三者都是字符串，不得出现数组、对象或其他大纲字段。

```json
{
  "kind": "outline",
  "data": {
    "highlights": "悬念40% / 逆袭30% / 对抗30%。第1集沈砚当众比对笔迹，证明旧案卷宗被人改过；第2集档案馆断电，陆行舟抢回被抽走的两页原件；第3集沈砚被停职后反向设局，引周启明露出破绽；第4集录音在听证会上公开，沈砚自证并反诉诬陷。",
    "ending": "OE：旧案重审，周启明被带走；沈砚提交辞呈后走出法医中心，雨停，她是否留下没有明说，镜头停在她重新戴上的手套，情绪落在未定的平静。",
    "paywall": "第2集结尾：沈砚刚打开封存档案，发现最后一页签着自己失忆前的名字，门外同时响起脚步声；来人与签名真伪留到第3集揭晓。全剧一个卡点，约占集数一成五，落在攀升转风暴的中段。"
  }
}
```

## 硬性约束

- 只输出三个字段，三者都必须是字符串。
- 三个字段都必须非空，不得用「待定」「略」占位。
- 爽点必须标明集数、动作与情绪兑现，禁止空泛形容。
- 结局类型只能取 `HE`、`BE`、`OE`，不得写「高潮悬停」「开放收束」等中文替代。
- 不新增原文没有的关键反转来制造爽点，不给没有感情线的故事强加恋爱。
- 付费卡点必须落到存在的集号与具体悬念，不能只写「中段设置收费」。
- 原文信息不足时先问一个具体问题，不得编造结局。
- 说明文字不得放进 JSON。

## 交付前自检

- data 是否恰好三个字段，是否全部为字符串。
- 爽点配比是否合计一百，每条是否都有集数、动作与情绪兑现。
- 结局类型是否三个字母之一，是否与原文收束一致，是否写了最后一场戏。
- 卡点数量是否约为一成到一成五，位置是否在中段转折，集号是否存在。
- 是否没有把卡点写成原文不存在的事件。
- 回复末尾是否只有一个 JSON 代码块，`kind` 是否为 `outline`。
