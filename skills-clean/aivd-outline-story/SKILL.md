# 大纲子步骤：故事线与三幕

## 职责

只写故事主干：一句话故事、完整走向、主角的表层欲望、深层需求、性格缺陷、三幕升级与整体节奏。角色名单、世界规则、爽点清单、结局类型、付费卡点、分集摘要都不要碰。

## 读什么

- 原文全文，按章节理清事件因果链与人物选择。
- 选题页的题材、调性、集数与创作方向。
- 已通过的角色与时空结果，人物称呼、职务必须保持一致。

## 怎么写

### 故事命题

- `logline`：一到两句，写清主角、目标、阻力、代价，并把核心冲突点出来；不要把最终反转和结局写进去。
- `synopsis`：一段完整走向，按时间顺序交代起点失衡、三次升级、最低点、最终选择。停在原文结尾，原文没写完不要往后编。

### 人物动力

- `want`：主角自己承认、会主动去追的东西。
- `need`：他真正缺失但未必自知的东西，必须与 `want` 形成拉扯，不能写成同义句。
- `flaw`：会直接导致失败、伤害他人或错失机会的性格问题；「太善良」「太要强」不算缺陷。
- 三者都要从原文的选择与后果里归纳，不要安一段原文没有的人物弧光。

### 三幕

每个 `act` 都写成一段文字，段内依次交代集数区间、事件、关系或转折、收束。不要把三幕写成数组或对象。

- `act1`：常态被打破、目标出现、主角被迫入局；写清本幕结束时的新处境，以及主角与关键人物的关系起点。
- `act2`：阻力连续升级，至少两次重大转折；第一次改变筹码，第二次改变关系或立场，把冲突从外部压到内部。
- `act3`：由前两幕因果逼出不可回避的选择，回收主要伏笔，落到最后一场戏。

三幕区间必须连续、不重叠、不跳空，合起来覆盖第 1 集到最后一集。集数分配参考第一幕约 15%、第二幕合计约 65%、第三幕约 20%。

### 节奏

`rhythm` 写成一段文字，但内部要覆盖五个层次：

1. 起势：前几集用什么钩子抓人，约占总集数 15%。
2. 攀升：冲突如何加码，约占 30%。
3. 风暴：压力最大、反转最密的段落，约占 35%。
4. 决战：集中释放与收束，约占 20%。
5. 波形：用一句话概括情绪曲线，例如「羞辱下压→结盟抬升→失证再压→公开释放」。

每一层都要标出大约落在哪些集，并与选题集数、单集时长匹配。

### 事实边界

- 事情先后要与分集顺序一致，后文才发生的事不得写进前面的幕或梗概。
- 谁做的事、谁说的话不得换人；反问不得改成对方已经承认。
- 同一集里的动作顺序不得颠倒；某句判断要挂在原文所指的那件事上。
- 人物的猜测、担心、事后才想起的信息，不得写成已经发生的事实。
- 不新增原文没有的关键转折、人物关系或结局。

## 输出

kind 固定为 `outline`，data 只允许九个字段：`logline`、`synopsis`、`want`、`need`、`flaw`、`act1`、`act2`、`act3`、`rhythm`。不得出现 `characters`、`episodes`、`highlights`、`ending`、`paywall`。

```json
{
  "kind": "outline",
  "data": {
    "logline": "失忆法医沈砚在连环旧案里认出自己的笔迹，必须在自证清白与揭开真相之间选择。",
    "synopsis": "沈砚回到故乡任职，三起旧案出现相同手法。她顺着证物找到失忆前的笔记，与刑警陆行舟结盟查档。关键证人失联后，她又发现自己曾为死者做过伪证，合作破裂；疗养院录音揭示她当年是被迫配合。最终她公开证据、接受调查，旧案重审。",
    "want": "沈砚想破案，并找回失忆前的真相。",
    "need": "她需要承认自己可能伤害过别人，仍然选择承担后果。",
    "flaw": "过度相信物证，遇到质疑就独自行动，把同伴排除在外。",
    "act1": "第1集：第三起旧案出现，沈砚在证物袋里看到自己的旧签名；她隐瞒关联私下比对，被陆行舟察觉，两人从互不信任转为被迫合作。",
    "act2": "第2至3集：两人结盟查档，关键证人在约定地点失联；沈砚被证实曾为死者做伪证，陆行舟中止合作；她在疗养院找到失忆前的录音，发现自己当年被迫配合，冲突从查案转为自证。",
    "act3": "第4集：录音公开，沈砚主动交出证据并接受调查，旧案重审；她在职业与真相之间做出选择，回到法医中心面对同事。",
    "rhythm": "起势15%（第1集）：旧案与旧签名钩子；攀升30%（第2集）：结盟查档、证人失联；风暴35%（第3集）：伪证曝光、合作破裂、录音反转；决战20%（第4集）：公开证据、旧案重审。波形为疑点收紧→信任崩塌→录音下压→自证释放。"
  }
}
```

## 硬性约束

- 只输出九个字段，不得夹带角色、爽点、结局、卡点或分集。
- 九个字段都不得为空字符串或占位词，每个值都要能直接进大纲。
- `act1`、`act2`、`act3`、`rhythm` 必须是字符串，不得写成对象或数组。
- 三幕区间必须连续覆盖全剧，第二幕至少两次转折。
- `want` 与 `need` 不得同义重复，`flaw` 必须造成实际后果。
- 不新增原文没有的主要事件或反转，不把故事写到原文结尾之后。
- 原文信息不足时先问一个具体问题，不得用占位词填空。
- 说明文字不得放进 JSON。

## 交付前自检

- data 是否恰好九个字段，是否全部非空。
- 三幕区间是否连续覆盖第 1 集到最后一集，第二幕是否有两次转折。
- 节奏五层是否齐全，比例是否与集数对得上。
- `logline` 是否含核心冲突且不剧透结局，`synopsis` 是否停在原文结尾。
- 人物称呼与职务是否与角色时空步骤一致。
- 回复末尾是否只有一个 JSON 代码块，`kind` 是否为 `outline`。
