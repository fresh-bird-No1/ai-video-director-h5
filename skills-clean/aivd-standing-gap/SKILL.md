# 智能补全站位卡

## 职责

按集扫分镜，挑出真正需要站位图的调度瞬间补卡。判断标准是这组空间关系会不会被反复拍摄、会不会因为站位错乱而接不上。已有站位卡不改、不合并、不覆盖；同一场同一组人物关系已经覆盖的，不再补第二张。

## 读什么

- 选题：画风与调性，保证新增卡画面气质统一。
- 创作大纲：人物关系与冲突节点，用于判断哪些瞬间值得锁位。
- 分集剧本：场次编号、地点、走位与动作描写，确认调度依据。
- 分镜：镜号、景别、机位和画面描述，是集数、场次、镜号的唯一来源。
- 场景卡：门位、家具方位与固定地标，新增站位不得与之冲突。
- 现有站位卡：`episode`、`shot`、`name` 与入画人物，逐条排除已覆盖的瞬间。

## 怎么写

- 先列候选：多人同框、有明显前后景关系、有逼近或退让、有堵门挡路、有交递与包围的镜头优先。
- 再筛掉：单人特写、纯环境空镜、只拍手部或物件的镜头，不建站位卡。
- 去重看三件事：同一集、同一场、同一组人物关系。已有卡覆盖该调度的跳过；相邻几镜若站位几乎不变，合并为一张并在 `shot` 写镜号范围；站位关系变了（左右对调、前后换位、入画人数变化）才拆新卡。
- 只在选题或大纲里提到、剧本和分镜都还没拍到的调度，不建卡。
- `name` 用能识别场次的短名，如「第5集 玄关摊牌 · 门口堵截」，同一集内不得重名。
- `episode` 填整数；`shot` 写成「第几场 · 镜几杠几」，必须精确到场次与分镜，禁止只写集数或「某镜」。没有分镜号时写动作节拍并注明「暂无分镜号」，场次仍要写全。
- `function` 写清这一瞬的叙事目的：谁占据高位、谁被逼到墙角、距离从几步缩到几步、谁封住出口。
- `description` 写相对位置、身体朝向、视线落点与间距；`lighting` 写光源方向与各自受光面；`landmark` 用场景卡已有地标做参照，写明谁靠着、谁挡着；`style` 沿用项目画风。
- 可选字段 `sceneName`、`characterNames`、`propNames` 要与资产库原名一致；没有对应项时用空数组或空串。
- 信息不足时按 `function` 反推最简调度，不擅自增加人物、改变场景结构或编造不存在的动作。

## 输出

`kind` 固定为 `standings`。`data` 可以是 `{ "standings": [...] }`，也可以直接是数组；数组里只放本轮新建的卡。没有缺口时输出空数组。

回复末尾附一个 JSON 代码块，代码块外说明补了哪几集、依据哪几个镜号。

```json
{
  "kind": "standings",
  "data": {
    "standings": [
      {
        "name": "第5集 玄关摊牌 · 门口堵截",
        "episode": 5,
        "shot": "第3场 · 镜5-2",
        "function": "继母带人堵死唯一出口，把女主从屋里逼到玄关，用身体封门表现她已无退路。",
        "description": "继母站在玄关内侧正中，正面朝屋，双肩打开，身后半步跟一名西装男；女主背对大门，被逼到鞋柜与门框之间，侧身抬头，视线越过继母肩膀看向屋内。两人间距不足一步，西装男封住右侧通道。",
        "lighting": "玄关顶灯在两人之间落下锥形光，继母面部受光完整；女主大半身处在门框阴影里，只有下颌与锁骨被照亮。",
        "landmark": "女主右肘几乎碰到门后的黄铜伞架；鞋柜横在她左膝前；继母脚边是玄关地毯的深色包边。",
        "style": "写实都市剧质感，冷暖交界明显，中近景略带仰角，浅景深。",
        "sceneName": "沈家老宅 · 玄关",

      }

  }

```

## 硬性约束

- 不得为单人镜头、空镜、纯道具特写建站位卡。
- 不得遗漏 `shot` 或只写集数；场次与分镜号必须同时出现。
- 不得输出已有站位卡，不得修改已有卡的任何字段，也不得用同名第二张卡覆盖。
- 不得把同一集、同一场、同一组人物关系的调度重复建卡。
- 不得编造素材里没有的走位、人物或空间结构。
- 不得与场景卡的地标位置、门向、家具布局矛盾。
- 不得输出出图提示词、版式、英文说明或图片地址。
- 任一必填字段为空，整张卡视为不合格；不得用「大概」「附近」「若干人」描述距离。
- 用户点击「写入草稿」之前，不得声称已写入。

## 交付前自检

- 是否先列出已有站位的集数、场次、镜号与人物，再确认新增卡不重复。
- 每张卡的集数、场次、镜号是否都对得上分镜表。
- `function` 是否写出可复述的权力关系或距离变化。
- `description` 是否精确到朝向、视线与间距。
- `lighting` 是否分人交代受光面，`landmark` 是否与场景卡一致。
- `sceneName`、`characterNames`、`propNames` 是否与资产库原名一致。
- `style` 是否与项目画风一致。
- JSON 块是否可解析，有无尾逗号与注释。
