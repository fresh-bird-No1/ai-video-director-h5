# 资产出图与回填

## 职责
拿资产卡里已经定稿的提示词去发起一次出图，把返回的图片地址与提示词一起交回，供页面写进对应的资产卡。若当前环境没有可用的出图服务，就退化为只交付最终提示词，并说明不能出图的原因。本技能不重写提示词，不改版式，也不替用户决定是否写入。

## 读什么
- 目标资产卡：类型（角色 / 场景 / 道具）、名称、已保存的提示词。
- 提示词是否完整：有没有分段、有没有写明画布比例与分区。
- 页面当前的出图能力：是否配置了服务、是否返回图片地址、是否有失败信息。
- 若提示词为空或明显只有半段，先指出缺什么，再决定是否出图。

不做风格改造，不把英文提示词译成中文，也不合并多张资产卡。

## 怎么写
先判断，再执行，最后如实汇报。

第一步确认目标：读资产卡的类型与名称，确认提示词是定稿版本；一个请求只处理一张资产卡，避免把别人的图写到这一张上。

第二步发起出图：把提示词原样送进出图流程，不删段、不加戏、不改比例；一次只提交一张图，便于定位失败原因。

第三步处理结果：成功时记录图片地址与出图所用提示词，地址要与这张资产卡一一对应；失败时保留错误信息的关键句，不编造地址，不拿旧图顶替。

第四步退化处理：没有可用服务时，直接输出这段最终提示词，并说明「当前没有可用出图服务，未生成图片」，把 image 留空字符串。

第五步说明可粘贴性：告诉用户这段 prompt 可以直接拿去外部模型使用，版式与画布比例已经在文本里写明。

## 输出
先用中文说明目标资产、执行结果或退化原因，末尾附代码块，kind 与目标资产类型保持一致：

```json
{"kind":"characterPrompt","data":{"name":"角色名","prompt":"最终提示词","image":"图片地址"}}
```

场景用 scenePrompt，道具用 propPrompt；出图失败或没有服务时 image 为空字符串，不得填占位链接。name 与资产卡名称完全一致。

## 硬性约束
- 回复最末必须是 JSON 代码块，且只有一个对象；说明文字不得写进 JSON。
- kind 只能是 characterPrompt、scenePrompt、propPrompt 三者之一，与目标资产对应。
- data 必须含 name、prompt、image 三个字段，prompt 用资产卡里的定稿文本。
- 不得声称已写回资产卡；写入由用户在页面上点「写入草稿」完成，之前只能表述为待写入。
- 不伪造图片地址，不静默改写 prompt，不一次返回多张资产的图。

## 交付前自检
- 目标资产类型与 kind 是否匹配。
- prompt 是否与资产卡定稿一致、是否保留分段。
- 成功时 image 是否为真实地址，失败时是否为空并说明原因。
- 是否避免声称已写入。
- JSON 是否可解析、三字段是否齐全。
- 说明文字是否全部在代码块之外。
