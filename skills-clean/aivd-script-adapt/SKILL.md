# 原文还原单集剧本

## 职责
把 `sourceText` 这一段已经拆好的本集原文，按原有顺序完整落成场次、场景卡和道具卡。台词一个字都不改，情节一句都不加；遇到原文没有单独建卡的地点或关键物件，顺手补进本集资产。只做当前这一集，不续写后文。

## 读什么
- `sourceText` 与 `sourceScope`：`sourceScope` 是 `episode-slice` 时，这段就是本集的全部素材，不要再去上传的全文里找别的段落。
- 选题：`dialogueLang`、画风锁定项、每集时长。每集时长优先看 `episodeDurationSec`，没有则从 `topic.duration` 解析。
- `adapt`：改编幅度。没给时按抽核处理。
- 角色设计：`characters` 里的 `name` 是主称谓，`aliases` 是同一人的其他叫法；`characterNames` 是主称谓名单，`speakerAlias` 是别称到主称谓的对照。
- 角色卡的 `language`：只作为后续配音参考。本技能台词必须逐字照抄 `sourceText`，原文是什么语种就保留什么语种，不按 `language` 翻译或换语种。
- 现有场景卡与道具卡名称：原文写到同一地点或同一物件时，必须沿用已有名字。
- 本集集号与标题；`priorEpisodeScripts`（前集已完成的剧本）；`revise_script`、`currentScenes`、`reviseRequest`（改写当前剧本时使用）。

## 怎么写

### 先拆事件，再落场次
1. 把 `sourceText` 按段落编号，用一句话记下每段发生了什么，标出转折、关键动作和关键台词。每段都要在场次里有落点。
2. 按原文顺序分场：地点或时间一变就另起一场，同一地点连续发生的动作可以并成一场。后发生的事不能挪到前面，别的集的内容不能提前写进来。
3. 一场只承担一个叙事任务，`heading` 写成「地点 · 日/夜 · 内/外」，地点名用原文里的叫法，不要另起地名，也不要把一句剧情当成场次标题。

### 三类行严格分开
4. 每场正文由三类行组成，一行只做一件事：
   - `action`：看得见的动作、环境、物件变化和画面读数。动作行里绝对不能出现「角色名：台词」。
   - `voiceover`：画外叙述，不写说话人。
   - `dialogue`：角色真正说出口的话，必须带 `speaker`，可带 `emotion` 表演提示。
5. 原文的「角色：台词」只能写成 `dialogue`，冒号后面的原句逐字照抄。不要把这种整句塞进 `action`，也不要先写进行动再在末尾重抄一遍。
6. 动作、旁白、对白不能叠在同一条里；两个人的台词不能合成一条。同一句对白只出现一次。
7. 括号里的动作、神态、沉默、环境，以及没说出口的心理活动，都写成 `action`，不要伪装成对白。原文是心想、猜测的，不要改写成角色开口。

### 说话人统一
8. `speaker` 只写主称谓。原文写「老陈」、角色设计里这个人叫「陈国栋」，说话人就写「陈国栋」；别的叫法可以留在对白正文里，但不要再当成另一个说话人。
9. 仪器、扫描、读数、速率、百分比、时间戳、纯数字、屏幕、白板、字幕、记录、日志、系统、标注、广播、警报、对讲机本身都不是说话人。它们的内容写成 `action`；对讲机里如果是某个角色在开口，说话人写那个角色。
10. 名字后面不挂情绪、渠道或动作。「老陈（通讯，带着电流杂音）」「宋瑶（自言自语）」这类写法不合格：说话人只留姓名，电流声、自言自语另起一行 `action`。

### 长度与改编幅度
11. 每场 `durationSec` 必填，正整数；对白按每秒约 4 个汉字估算（英文按每秒约 2.5–3 个单词，日文按约 4–5 个字/假名），动作按实际演出时间估算，不能按描述字数折算。
12. `faithful` 忠实：关键情节不能删，人名沿用原文，台词仍逐字照抄；整集可以因原文篇幅略超预算，但不得无故加戏。
13. `extract` 抽核（默认）：只有给了 `episodeDurationSec` 才压到该秒数；没有这个字段时按原文篇幅自己把握，禁止默认套用 60 秒。对白压缩只允许整句删除，留下的句子仍照抄原文。
14. `shell` 借壳：允许换场面，人物关系和转折必须来自原文，台词仍然用原文原句，不能换成另一个故事。
15. 场次数一般 4–10 场；忠实型可随原文情节略增。抽核与借壳按预算估算，每场 20–30 秒，整集合计贴近或等于 `episodeDurationSec`。
16. 原文换行后的句子要继续输出，各自单独成行；`text` 必须是完整句子，不能只留前半句，也不能用省略号代替后半句。

### 建卡与改写
17. `places`、`props` 与 `scenes` 同级输出，只补这一集真正出现、现有资产又没有的条目。同一物理地点只写一次；已有名称不得另起新名。
18. `places` 字段为 `name`、`description`、`location`、`lighting`、`landmark`、`style`；`props` 字段为 `name`、`description`、`usage`、`material`、`size`、`style`。没有缺口就输出 `[]`。
19. `revise_script` 时在 `currentScenes` 上改，保留每行原有类型，按改后的正文重估该场 `durationSec`；判断对错仍以 `sourceText` 为准，未点名的场次和台词原样保留。
20. `priorEpisodeScripts` 只用来衔接人物、称呼和上一集结尾；当前集的情节与台词一律以 `sourceText` 为准，不要顺着前集自由续写。

### 不许写进正文
21. `本场悬念`、`下场预示`、`场景概要`、`场景类型`、`出场角色`、`戏剧目标`、`情绪基调` 是场记，不是剧本内容，不能进 `lines`。
22. 不写「切黑」、镜号、特写、近景、远景、淡入淡出、出图提示词；也不把画风说明、单独的光线、材质磨损、尺寸、地标枚举写进正文，这些只留在 `places` / `props`。

## 输出
`kind` 固定为 `script`。`data` 含 `episodeNumber`、`title`、`scenes`、`places`、`props`。

每场同时给出两套等价视图，H5 会按类型归档：
- `number`、`heading`、`durationSec`：场号、标题行、时长。
- `title`、`location`、`time`：界面表单使用的场次标题、地点、时间。
- `lines`：每条带 `type`，取值 `action`、`voiceover`、`dialogue`；对白再带 `speaker`，可带 `emotion`。
- `actions`、`narration`：从同一批 `lines` 中按类型归并出来的兼容数组，内容必须与对应行逐字一致。

## 硬性约束
- 台词逐字照抄 `sourceText`：只能整句删除，不能换词、调序、截半句或用省略号代替后半句。
- 台词语种与原文一致，不按角色卡 `language` 翻译；角色卡 `language` 与原文语种不一致时，只在文字结论里提示，不改台词。
- `speaker` 一律用主称谓；别名通过 `characters.aliases` 或 `speakerAlias` 映射，不得另立说话人。
- 动作行不得出现「角色名：台词」；对白行不得夹动作；一条对白只能有一个说话人。
- 不是人的读数、屏幕、时间、系统不能当说话人；没说出口的心理不能当对白；画外叙述用 `voiceover` 且不写 `speaker`。
- 不添加原文没有的人物、台词、动机、私下对质和后续情节；顺序不得提前或倒置。
- 地点名沿用原文；`heading` 必须是「地点 · 日/夜 · 内/外」。
- 每场 `durationSec` 必填；抽核和借壳的整集合计要贴近 `episodeDurationSec`。
- `places`、`props` 只补现有资产没有的条目，没有缺口写 `[]`，不得与已有名称重复。
- 不写镜头号、场记字段、分镜和出图提示词。

## 交付前自检
- 对照原文段落，确认每一段都有场次落点，顺序与原文一致。
- 抽查所有对白，确认 `text` 与原文逐字相同，没有改写、截断或补写，且保留了原文语种，没有按角色卡翻译。
- 检查每条动作行，确认没有混入「角色名：台词」和括号里的对白。
- 检查所有 `speaker`，确认已从别名统一到主称谓，非人对象没有伪装成说话人。
- 检查 `number`、`heading`、`durationSec` 与 `lines` 的 `type` 是否齐全，`actions`、`narration` 与同类型行是否逐字一致。
- 确认 `places`、`props` 只补缺口，没有重名，字段完整。
- 确认末尾 JSON 能被 `JSON.parse` 解析，无注释、无尾逗号。
