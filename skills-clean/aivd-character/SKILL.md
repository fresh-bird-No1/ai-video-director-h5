# 角色卡设计

## 职责

把故事里已经确定的人整理成一张能长期复用的角色卡。卡面要同时交代三件事：这个人在剧情中承担什么位置、他是什么样的人、他说话是什么声音。只写卡面文字，不产出定妆图、视频提示词或图片地址。

## 读什么

- 选题：题材、受众、调性，以及 `visualStyle`（项目画风锁定）。它决定年龄层、气质、命名习惯和画风说明的写法。
- 创作大纲：角色名单、人物关系、三幕功能、结局走向，用来确定角色定位和人物弧光。
- 分集剧本：人物称呼、台词长短、动作习惯、服装线索，用来校准性格、口头禅与外貌。
- 分镜：画面里反复出现的外形特征，用来核对 `identityLock` 是否够具体。
- 已有角色卡：先读名字清单。同名人物一律沿用原卡，不重复建卡。

## 怎么写

- `name` 用稳定、可复用的角色名或固定称呼，不带集数、场次、镜号。
- `role` 只能取「女主」「男主」「反派」「配角」「功能角色」之一。功能角色是只推动单一情节的临时人物，如证人、前台、主治医生。
- `description` 是列表页的一句话：公开身份 + 他最想要什么 + 挡路的最大障碍，六十字以内，不写外貌。
- `gender`、`age` 写可直接用于选角和造型的性别与年龄感，如「女」「二十七八岁」。
- `ethnicity` 写角色的人种 / 族裔，要能直接指导选角与出图，如「东亚」「北欧白人」「非裔」「南亚」「拉丁裔」「混血（东亚/白人）」；不得只写国籍、民族泛称或「亚洲人」这类过于宽泛的写法。
- `language` 写角色台词使用的语种，如「中文」「英语」「日语」「韩语」「粤语」；该角色的剧本台词、分镜台词与音色试听都按这个语种，同一个人不得中途换语种。角色卡没写时按选题 `language` 兜底。
- `identity` 写外人眼里的公开身份；`trueIdentity` 写隐藏身份或真实背景。素材没有隐藏身份时，写目前能确认的真实处境，不另编一套身世。
- `appearance` 用两三句写外形：发型发色、脸型五官、肤色肤质、身高体型、常穿的衣服、辨识色或疤痕；肤色、骨相、发质必须与 `ethnicity` 一致，不能出现「东亚人设配金发碧眼」这类冲突。
- `personality` 写性格关键词，用顿号或逗号分隔，后续要能落到行为上。
- `motivation` 写核心欲望，`conflict` 写最大冲突点，`arc` 写这个人在现有剧情里的变化，一到两句。
- `tags` 给二到四个检索关键词；`relationships` 是数组，每项含 `name` 与 `relation`，对象必须是剧本或大纲里真实存在的人，没有可写关系时用 `[]`。
- `identityLock` 写不可改的外形锁：发型发色、体型骨架、辨识色、标志物、疤痕或固定配饰，至少三项可核验特征。下游定妆出图与视频生成必须逐条遵守，任何环节不得改动这些特征。
- `profile` 写成一段连贯的人物画像，依次覆盖六块：外形（含族裔、肤色、骨相、发质）、身份职业、性格底色与行为逻辑、核心欲望与恐惧、与他人的关系张力、标志性小动作或口头禅。六块缺一不可，不要写成标签堆砌。
- `voice` 是给语音合成读的参数说明，不是台词：写清性别、年龄段、音区高低、语速、咬字松紧、气声比例、情绪表达特征。`voiceAudio` 是卡片上的音频槽，由用户上传或生成音色，本技能不填、不清空。
- `styleNotes` 写这一角色的画风说明，一两句，覆盖笔触、色调、光质。必须与选题 `visualStyle` 完全一致，不得擅自换成半写实厚涂或其他画风，也不要写成整段定妆提示词。
- `costumes` 是服装列表，由服装技能维护；本技能不虚构服装条目，也不覆盖已有服装。
- 单卡补全：用户从某张卡点「补全信息」时，只处理这一张，补空缺、润色已有内容，保持原定位与原意；可输出单个角色对象，也可输出只含该角色的 `characters` 数组。批量建卡：按大纲名单一次输出多名角色。除当前点名的卡之外，不得改动任何已有角色卡。
- 剧本没写到的细节，按题材和人物处境补齐，补齐内容不得与大纲的关系、结局或已有卡冲突。

## 输出

`kind` 固定为 `characters`。`data` 可以是 `{ "characters": [...] }`，也可以直接是数组。每个角色至少包含下列文本字段，且全部非空：`name`、`role`、`description`、`gender`、`age`、`ethnicity`、`language`、`identity`、`trueIdentity`、`appearance`、`personality`、`motivation`、`conflict`、`identityLock`、`arc`、`tags`、`relationships`、`profile`、`voice`、`styleNotes`。

## 硬性约束

- 不得输出定妆提示词、画面提示词、英文版式、图片地址，也不得写 `imagePrompt` 或 `prompt`。
- 不得删除或覆盖已有角色的字段；批量模式只新增，单卡模式只改用户当前点名的那一张。
- `identityLock` 不得少于三项可核验特征，且必须明确写下游定妆与视频生成必须遵守。
- `ethnicity`、`language` 不得为空；`appearance` 与 `profile` 里的肤色、骨相、发质必须与 `ethnicity` 一致，不得写出互相冲突的族裔特征。
- `styleNotes` 必须与选题画风锁定一致，不得另起一种画风。
- 不得把 `profile` 写成关键词清单，不得把 `voice` 写成台词、旁白或配音演员姓名。
- 不得虚构 `relationships` 中不存在的人，不得把同一角色拆成两张卡。
- 任一必填字段为空，整张卡视为不合格；不得用「待定」「暂无」「未知」占位。
- 不得写场景调度或剧本对白。
- 用户点击「写入草稿」之前，不得声称已经写入项目或已保存。

## 交付前自检

- 上述文本字段是否逐项存在且都不是空串，`relationships`、`tags` 是否为合法数组。
- `role` 是否落在允许的五个取值内。
- `description` 是否同时读到身份、欲望、障碍。
- `ethnicity`、`language` 是否非空，`appearance` 与 `profile` 是否写出了与族裔一致的肤色、骨相、发质，`language` 是否能直接用于后续台词与配音。
- `profile` 的六块内容是否都能找到对应句子，而不是形容词堆叠。
- `identityLock` 是否具体到发型、体型、辨识色或标志物，能否直接约束出图与视频。
- `styleNotes` 是否与选题 `visualStyle` 一致。
- `voice` 的七项参数是否都能读出来，且没有混入台词。
- 是否误改了非当前卡片的角色，或重复建了同名角色。
- JSON 块能否直接解析，有无尾逗号、注释或中文引号。
