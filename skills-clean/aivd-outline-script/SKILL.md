# 从剧本生成大纲（总控）

## 职责

你只做编排与验收，不一次性把整份大纲硬写出来。把工作拆成四个可单独校验的子步骤，一次只走一步；每一步的字段齐了、值不空、类型对了，才允许进入下一步。最后把四份结果拼成一份完整大纲。

任何一步都不许顺带写别的步骤的字段。分集摘要只能由分集子技能写，三幕只能由故事线子技能写，结局与卡点只能由爽点结局子技能写，角色与时空只能由角色时空子技能写。

## 读什么

- 原文全文与章节结构，先建立「第几章到第几章」的范围清单。
- 选题页的集数、结局、题材、调性、受众与创作方向。
- 四个子步骤的返回结果，逐份校验，不把半成品并入总稿。
- 用户对某一步的单独修改要求，只作用在那一步。

## 怎么写

### 固定顺序

1. `aivd-outline-cast`：角色、时空、世界规则。
2. `aivd-outline-story`：故事线、欲望缺陷、三幕、节奏。
3. `aivd-outline-ending`：爽点、结局、付费卡点。
4. `aivd-outline-episodes`：一次一集，逐集摘要与看点。

顺序不得打乱，也不得把四步合成一次请求。分集数量多时，第四步按集循环，每集单独校验。

### 每一步的交付边界

- 角色时空：只收 `characters`、`setting`、`worldRules`。核对每个名字都能在原文找到依据，职务、辈分没有被抹掉。
- 故事线：只收 `logline`、`synopsis`、`want`、`need`、`flaw`、`act1`、`act2`、`act3`、`rhythm`。核对三幕区间连续覆盖全剧，第二幕至少两次转折。
- 爽点结局：只收 `highlights`、`ending`、`paywall`。核对爽点不重复、钩子不雷同、结局类型只取 `HE`、`BE`、`OE`，卡点落在存在的集上。
- 分集摘要：只收一条 `episodes` 记录，含 `number`、`title`、`synopsis`、`logline`。核对本集对应的章节范围、集号是否正确、摘要与看点是否说两件事。

### 校验规则

- 每步返回后先看键名：缺键、多键、把对象塞进字符串、把数组写成一句话，都判为不通过。
- 再看值：空字符串、空数组、「待定」「略」「同上」一律不通过。
- 分集记录额外看集号：必须等于总控分配的集号，不得跳号、重号，不得一次返回多集。
- 不通过就让该步补写或重写，不得用占位内容先合并。
- 合并时保持字段原名与顺序，不新增字段，不改变集数，不改写已经通过的句子。

### 合并前的一致性检查

- 角色名在三幕、爽点、分集里是否统一，是否有同一人两种写法。
- 三幕区间相加是否恰好覆盖第 1 集到最后一集。
- 每集摘要提到的事件是否能在原文找到；是否把后文事件提前。
- `ending` 是否与原文实际收尾一致；原文未完结取 `OE`，并在正文说明停在何处。
- `paywall` 的集号是否存在，悬念是否与本集及下一集内容对得上。
- `episodes` 条数是否等于选题集数。

### 正文说明

先用一小段说明本大纲依据原文第几章到第几章、集数如何对应章节，再给 JSON。说明放在 JSON 之外，不上交空话。

## 输出

## 硬性约束

- 四步不得跳过、不得合并、不得由总控代写任何子步骤的内容。
- 子步骤字段不完整时不得合并，不得用空值或占位词蒙混。
- 不新增原文没有的主要人物与关键事件，不把一章拆成多集。
- 集数不得偏离选题，编号必须连续到最后一集。
- 每个子步骤只返回自己负责的字段，返回里出现越界字段即判不通过。
- 正文说明不得写进 JSON；用户确认前不得声称大纲已写入项目。

## 交付前自检

- 四个子步骤是否都完成并逐份校验过，是否有越界字段。
- 合并稿是否字段齐全、类型正确、没有空值。
- 分集数量与编号是否连续，每集是否能对应到明确章节。
- 三幕区间是否连续覆盖全剧，第二幕是否至少两次转折。
- 结局是否与原文收束一致，付费卡点是否写明集数与悬念。
- 正文是否说明了依据的章节范围与集数依据。
- 回复末尾是否只有一个完整 JSON 代码块，`kind` 是否为 `outline`。
