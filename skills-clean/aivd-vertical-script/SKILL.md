# 竖屏漫剧剧本

## 职责
把本集梗概写成手机竖屏可以直接拆镜的场次。画面以近景为主，信息点前置，钩子密，台词短；同时给每场写清演出时长，保证整集落在预算内。只写这一集。

## 读什么
- 本集梗概或分集摘要：本集从哪里开始、必须完成哪个转折、停在哪句钩子上。
- 创作大纲：人物关系、世界规则、爽点位置、付费卡点，以及本集在全剧中的位置。
- 角色卡：正式称呼、身份、说话习惯，用来统一口吻和 `speaker`。
- 角色卡的 `language`（每人台词语种）：`lines` 的 `text` 按说话人自己的 `language` 写；没写时用选题 `dialogueLang` 兜底。同一角色全场不换语种，不同语种同场时各说各的，不翻译、不加括注。
- 前几集剧本：只接上一集结尾的情绪与悬念，不重复前集场次。
- 选题：`dialogueLang`、画风锁定项、`episodeDurationSec` 或 `topic.duration`。
- 用户本轮补充说明：与本技能默认规则冲突时，以用户说明为准。

## 怎么写

### 竖屏画面意识
1. 默认单人或双人近景，人物放在画面中下部，顶部只留少量空间，关键信息压在中央竖条区域。
2. 每场至少安排两个近景信息点：脸、手、手机屏、门缝、杯口、鞋尖、物件特写等。大场面用局部代替全景。
3. 同一场里人物站位变化不超过三次；窄画幅里人物关系一散，信息就漏。
4. 只写镜头看得见的东西。心理活动改写成动作、表情或物件变化，不写「她想起」「他明白」。

### 钩子密度
5. 开场三秒内出现冲突、异常或一句不对劲的话。
6. 每三到五秒给一次信息更新：一句反问、一次打断、一条消息提示、一个表情变化、一件东西出现。
7. 每场结尾留一个没有回答的问题；场与场之间靠因果咬合，不靠「后来」「第二天」硬切。
8. 第一场结束前必须出现反转或新信息，整集至少两次升级。
9. 对白一句不超过二十字（英文按 8–14 个单词控制）；语种按说话人角色卡的 `language`，不得为了统一而翻译。长信息拆成两三个回合，让角色互相打断、抢话、答非所问。

### 场次与时长
10. 一场一地点一时段，地点或时间一变就另起一场；每场只完成一个叙事任务。
11. 每场 `durationSec` 必填，正整数，建议 10–35 秒。对白按每秒约 4 个汉字估算（英文按每秒约 2.5–3 个单词），动作按画面真实占用时间估算。
12. 场次数由整集预算决定：
    - 预算不超过 60 秒：2–4 场。
    - 61–90 秒：3–6 场。
    - 91–120 秒：4–8 场。
    - 超过 120 秒：按每场 20–30 秒估算，最多 12 场。
13. 有 `episodeDurationSec` 时，所有场次 `durationSec` 相加必须正好等于它；没有则从 `topic.duration` 解析；两者都没有时按 90 秒预算，总和误差不超过 5 秒。

### 分行写法
14. 每场四块内容：`actions` 写可见动作与信息点；`narration` 写画外旁白；`lines` 写开口的话；`durationSec` 写这场演多少秒。
15. `actions` 一条一个动作单元，按发生顺序排；沉默、呼吸、停顿、脚步声都放这里。
16. `narration` 能不用就不用，用也只写一句，交代画面补不出来的前情或时间跳跃。
17. `lines` 每条只放一个说话人的一句话，按开口顺序排。`speaker` 用角色卡里的主称谓；别名先映射回主称谓。电话、广播里只闻其声、角色卡又没有收录的，用固定身份称呼，例如「电话那头」，全集只用一个叫法。
18. `text` 只留说出口的话，去掉引号、括号解释、心理提示和「他说」「她问」。
19. 动作、旁白、对白不能混进同一条；两个人的台词不能压在一条里。

### 不要写
20. 不写景别、焦段、运镜、分镜术语，也不写出图提示词；近景要求靠画面内容体现，不靠术语标注。
21. 不改人物姓名与关系，不新增大纲里没有的角色，不提前透支下一集。
22. 画风说明、单独的光线描述、材质磨损、尺寸、地标枚举不写进正文，避免和后续场景卡、道具卡重复。

## 输出
`kind` 固定为 `script`，`data` 含 `episodeNumber`、`title`、`scenes`。每场含 `title`、`location`、`time`、`actions`、`narration`、`lines`、`durationSec`；`lines` 每项含 `speaker`、`text`。

下面的示例按 `episodeDurationSec` 为 90 秒写，三场相加 32 + 30 + 28 = 90，可直接 `JSON.parse`：

```json
{
  "kind": "script",
  "data": {
    "episodeNumber": 2,
    "title": "第六个未接来电",
    "scenes": [
      {
        "title": "楼道来电",
        "location": "老楼楼道",
        "time": "夜",
        "actions": [
          "林晚收伞，水珠顺着伞骨滴在台阶上。",
          "手机在风衣口袋里震动，屏幕亮起第六个未接来电。",
          "她拇指悬在回拨键上，楼道声控灯突然灭了。"
        ],
        "narration": [
          "这是她搬进这栋楼的第七天。"
        ],
        "lines": [
          { "speaker": "林晚", "text": "谁啊，这么晚。" },
          { "speaker": "电话那头", "text": "你背后那扇门，别开。" }
        ],
        "durationSec": 32
      },
      {
        "title": "门内",
        "location": "老楼走廊",
        "time": "夜",
        "actions": [
          "她回头，走廊尽头那扇门开了一条缝。",
          "门缝里伸出一只湿手，指尖点着地面。"
        ],
        "narration": [],
        "lines": [
          { "speaker": "林晚", "text": "谁在里面？" }
        ],
        "durationSec": 30
      },
      {
        "title": "退路",
        "location": "老楼楼梯",
        "time": "夜",
        "actions": [
          "声控灯重新亮起，楼梯口站着一个人影。",
          "林晚攥紧伞柄，后退半步，鞋跟抵住台阶。"
        ],
        "narration": [],
        "lines": [
          { "speaker": "电话那头", "text": "别回头，往下跑。" },
          { "speaker": "林晚", "text": "你到底是谁？" }
        ],
        "durationSec": 28
      }
    ]
  }
}
```

回复末尾必须附一个 `JSON` 代码块，形如 `{"kind":"script","data":{...}}`。场次说明和写作思路写在代码块外，不能塞进 JSON。用户点击「写入草稿」之前，不得声称已经保存。

## 硬性约束
- 每场 `durationSec` 必须是正整数，全集相加要落在预算内，不能只写场次不管总时长。
- 场次数必须符合当前预算档位，禁止开场很多、每场只有两三秒的凑数写法。
- `actions`、`narration`、`lines` 三类分行，所有台词都能直接朗读。
- `speaker` 与角色卡称呼一致；同一人不得两个叫法；电话、广播等只闻其声的角色用固定身份称呼。
- 每句台词的语种必须与说话人角色卡的 `language` 一致；不同语种同场时不做翻译或括注。
- 不写心理描写、镜头术语、配乐提示、分镜和出图提示词。
- 不留空字段：没有旁白时 `narration` 写 `[]`，不要用空字符串占位。
- 时间与地点写法前后统一，`time` 用 日、夜、清晨、傍晚这类简洁词。

## 交付前自检
- 开场三秒内是否有冲突或异常，第一场结束前是否给了反转或新信息。
- 每场是否至少有两个近景信息点，每三到五秒是否有一次信息更新。
- 每场结尾是否留了未解问题，场与场之间是否靠因果衔接。
- 每场 `durationSec` 是否为正整数，所有场次相加是否等于或贴近整集预算。
- 三类内容是否分行，台词是否都能直接念出来，`speaker` 是否统一。
- 每句台词是否使用说话人角色卡的 `language`，没有中途换语种或翻译。
- 本集是否只完成梗概要求的情节，没有提前写下一集。
- 末尾 JSON 能否被 `JSON.parse` 直接解析，代码块外没有重复正文。
